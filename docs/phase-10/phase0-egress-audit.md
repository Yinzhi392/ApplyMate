# 阶段 0.13 外发链路审计

**执行日期：** 2026-08-11（阶段 10.6 复核）

**结论：** 通过。本步骤只使用完全合成数据，不处理真实简历、岗位截图或用户信息。

## 审计方法

1. 将一张包含合成手机号、邮箱、身份证号、护照号和详细地址的固定临时 PNG 作为 `GeneralBasicOCR` 的 `ImageBase64` 参数提交给腾讯 OCR。
2. 初版仅在 API Explorer 中实际调用 OCR，无法证明本地 TC3 请求的真实外发。阶段 10.6 改为同一受控脚本直接签名并调用 OCR；OCR 的响应只在进程内拼接为待脱敏文本，完成后立即丢弃。本次 OCR 耗时 1,743 ms。
3. OCR 文字在本地通过唯一脱敏边界，五类敏感信息全部替换后才构造 TokenHub 请求。
4. 使用 `hy3` 发起一次最小验证请求，并在发送前检查完整请求体。TokenHub 返回 HTTP 200，耗时 2,107 ms，共使用 126 Tokens。

## 数据边界结果

- 原始图片内容只存在于腾讯 OCR 请求，不进入 TokenHub。
- TokenHub 请求不包含图片、Base64、文件标识、手机号、邮箱、证件号或详细地址。
- 仓库证据只保存目标域名、请求方法、内容类型、载荷字节数、SHA-256、边界布尔值、模型名、耗时和 Token 数。
- 仓库不保存原始请求体、认证值、OCR 完整响应、模型响应正文或云端请求标识。
- 本次实际 OCR 文本命中并遮盖 5 类受保护信息；固定临时 PNG、旧 SVG 源和旧 OCR 文本均在审计后删除。

机器可读证据见 [`phase0-egress-audit.json`](./phase0-egress-audit.json)。该文件已通过结构验证和敏感内容反向扫描。

## 免费额度复核

- 初版的 OCR 免费包已用量由 33 增至 34，剩余 44,016；设置页仍显示后付费模式关闭。阶段 10.6 的技术审计不把旧快照伪装为本次账单结论；OCR、TokenHub、CloudBase、存储和流量的统一实际费用复核仍严格留在 10.12。
- TokenHub 控制台仍显示 `hy3` 剩余 96.9%、`deepseek-v4-flash` 剩余 99.8%，两者按 Token 计费均未启用。
- 本步骤没有购买资源包或打开付费兜底。跨 OCR、TokenHub、CloudBase、存储和流量的最终 0 元结论仍由 0.14/10.12 单独审计。

## 限制

本步骤证明的是“直接 TC3 OCR 请求 + 本地脱敏 + 直接 TokenHub 请求”的数据边界。真实 CloudBase worker、事务仓储、异步派发和生产网络采集器尚未部署，因此不得把本结果解释为云端运行时已经发布或通过端到端生产审计。阶段 0.14 的历史成本审计不替代发布前 10.12 的再核对。

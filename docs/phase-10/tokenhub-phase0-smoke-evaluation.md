# TokenHub 阶段 0.12 冒烟评测记录

**评测日期：** 2026-08-11
**样本版本：** `phase0-v1.0`
**当时结论：** 原单模型冒烟门禁失败，当时未启动 30 组全量评测。本文保留历史失败证据；产品负责人后续确认调整方案，正式结果见 [`tokenhub-phase0-evaluation.md`](./tokenhub-phase0-evaluation.md)。

## 安全与范围

- API Key 名称为 `applymate-phase0-eval`，控制台显示启用且只允许 2 个推理服务；密钥仅保存在被 Git 忽略的 `.env.phase0.local`，文件权限为 `0600`。
- 评测器固定 TokenHub 广州 OpenAI 兼容地址，只允许 `deepseek-v4-flash` 与 `hy3`，并要求 `TOKENHUB_PAID_FALLBACK=disabled`。
- C01 输入来自已锁定的完全虚构样本。出站前使用确定性规则遮盖手机号、邮箱、证件号和详细地址；检查点只保存哈希、Token、耗时和布尔判定，不保存简历、JD、Prompt 或模型原文。
- 全量计划为 30 组 × 2 模型 × 3 任务，共 180 次调用；悲观估算每模型 36 万 Token。由于冒烟失败，全量没有执行。

## 冒烟结果

| 模型 | 结构化 | 生成 | 改写 | 判定 |
|---|---|---|---|---|
| `deepseek-v4-flash` | Schema 通过；六字段 3/6；11,056 ms；1,568 Token | 45 秒截止后中止 | 未执行 | 不满足准确率和时延门槛 |
| `hy3` | Schema 与六字段均通过；2,473 ms | Schema/证据/零虚构通过；178 字；10,539 ms | Schema/零虚构通过；198 字、1 项 claim 对齐失败；9,696 ms | 不满足 250–350 字与 ≥95% 合规率 |

Hy3 在两次有限 Prompt 修订中仍只生成 162–198 个可见字符。最终一次三项共使用 3,444 Token；三次 Hy3 冒烟合计已知使用 10,310 Token。DeepSeek 已知完成调用使用 1,568 Token，超时调用的服务端实际计量没有在本地响应中返回。

## 免费额度复核

- 调用后 `deepseek-v4-flash` 显示剩余 99.8%，`hy3` 显示剩余 99%。
- 两个模型继续显示“按 Token 计费未启用”，没有开启 Token Plan、Coding Plan 或其他模型。
- 本记录只证明控制面仍处于免费失败关闭状态；跨平台实际账单总审计仍属于 0.14/10.12。

## 停止决定

冒烟已经证明当前单请求 Prompt 与两种候选模型不能同时满足：结构化正确、文案合规率 ≥95%、零虚构和中位耗时 ≤10 秒。因此不消耗剩余额度运行 30 组，不进入 0.13。下一步必须先由产品负责人确认是调整产品长度门槛、采用确定性扩写/两阶段生成，还是更换已授权范围内的模型方案；开发者不得自行启用付费或新增平台。

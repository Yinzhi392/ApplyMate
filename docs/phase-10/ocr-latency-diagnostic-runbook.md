# 阶段 0.11R OCR 时延诊断运行说明

本说明只适用于完全合成的 `phase0-v1.0` 图片，不得替换为真实简历、真实 JD 或用户截图。

## 前置人工核对

在执行真实调用前，产品负责人须在腾讯 OCR 控制台确认：后付费关闭、剩余免费调用数不少于 102、当前实际账单为 0 元。该步骤不接入 CloudBase，也不调用 TokenHub。

## 命令顺序

1. `npm run ocr:latency:plan`：离线显示固定 72 + 30 的调用预算。
2. `npm run ocr:latency:prepare`：仅在 `/private/tmp/applymate-phase0-ocr-latency` 生成 90 张合成变体。
3. `npm run ocr:latency:diagnose`：命令内置预检确认标识，顺序执行 72 次 OCR，输出安全诊断证据。没有胜出变体时自动删除临时图片。
4. 只有诊断报告存在胜出配置时，才执行 `npm run ocr:latency:full` 进行 30 组全量复验；完成后自动删除临时图片。
5. 若中断或无需全量复验，执行 `npm run ocr:latency:cleanup` 删除临时合成图片。

环境变量只从 Git 忽略的 `.env.phase0.local` 读取。任何命令都不得显示、复制或写入密钥、OCR 原文、图片 Base64、RequestId 或用户内容。

## 通过判定

候选变体必须在 24 次代表性调用中零超时、字段准确率至少 90%、中位端到端耗时不超过 10 秒。全量复验必须在 30 组中再次满足字段准确率至少 90%、中位不超过 10 秒、所有调用严格小于 45 秒。

复验完成后，产品负责人再次核对 OCR 控制台后付费关闭和实际费用为 0 元。即使通过，也只能更新阶段 0 决策，不能自动进入 0.17 或发布流程。

# TokenHub 阶段 0.12 调整后正式评测

**评测日期：** 2026-08-11

**样本版本：** `phase0-v1.0`

**结论：** 30 组正式评测通过阶段 0.12 设定的字段、文案、虚构和耗时门槛。

## 调整方案

原单模型冒烟评测中，DeepSeek 字段/耗时失败，Hy3 生成文案长度失败。经产品负责人确认后，正式方案改为：

1. Hy3 每组只调用一次，解析六类 JD 字段，并从已确认简历事实中选择 2–4 个 `factId`。
2. 首次开场白和改写均由本地确定性渲染器生成，仅使用模型选中的有效事实和 JD 字段。
3. 本地质量门仍强制 250–350 个可见字符、2 段、逐项证据和禁止事实检查。

该方案将模型的语义判断与文案格式控制分离，不调整产品长度或事实门槛。

## 30 组结果

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| Hy3 外部调用 | 30 次 | 每组 1 次 |
| 本地生成/改写 | 60 次 | 不外发 |
| 六类字段准确率 | 178/180，98.89% | ≥90% |
| 文案合规率 | 60/60，100% | ≥95% |
| 虚构数 | 0 | 0 |
| 端到端中位耗时 | 3,410 ms | ≤10,000 ms |
| TokenHub 已知 Token | 20,008 | 免费额度内 |

C14 的“地点/工作方式”和“到岗/时长”两个冲突字段判定不正确，其余 178 个字段判定正确。这两项不得进入文案；本地渲染器未把它们写入候选人事实。

## 安全与成本状态

- 请求只包含锁定的脱敏合成文本，不包含图片、真实简历或 JD。
- 临时检查点只保存哈希、时延、Token、字段布尔结果和 `factId`，不保存原始 Prompt 或输出。
- 评测后 Hy3 免费额度剩余 96.9%，`deepseek-v4-flash` 剩余 99.8%；两者“按 Token 计费”均为未启用。
- 0.12 通过时尚不能代替后续门槛；0.13 外发链路和 0.14 五类资源零费用审计现已分别通过，发布前 10.12 仍须再复核。

## 运行证据

- `npm run tokenhub:smoke -- --model=hy3`：C01 字段 6/6，合规率 100%，零虚构，2,686 ms，813 Token。
- `npm run tokenhub:full -- --model=hy3`：30 次外部结构化调用和 60 次本地渲染完成。
- `npm run check`：正式评测与文档同步后，100 个测试文件、359 项测试及五模块构建通过。

# 《投了吗》ApplyMate 正式产品设计

**版本：** Public Mobile Web v3.0
**生效日期：** 2026-08-23
**状态：** 已批准，作为当前产品基线
**详细规格：** `docs/superpowers/specs/2026-08-23-mobile-web-public-v3-design.md`

本文是产品规则的唯一当前基线。微信小程序、邀请码、匿名登录、Hash 路由、PWA、AI 改写和“零付费体验版”均为历史口径，不得用于正式 Web。微信最终版固定在 Git 标签 `legacy-miniprogram-final`（提交 `b99be7e`），源文件仅作归档，不参与主构建或发布。

## 1. 产品定义

ApplyMate 是只面向手机浏览器的公开网站。用户提交已确认简历和岗位文字或截图，系统提取岗位要求，从简历事实中选择证据，生成带明确 AI 标识的求职开场白，并保存投递记录。

产品承诺：

- 只使用用户核对确认的简历事实，不根据常识补写经历。
- 原图只发送给 OCR；进入 TokenHub 的文本先做本地脱敏。
- 生成正文与复制内容均带“AI 生成内容，请核对真实性”标识。
- 移动优先，支持 iOS Safari、Android Chrome 与微信内置浏览器；电脑仅显示居中的手机版画布。
- 正式模型固定为 TokenHub `hy3`，不自动切换备用模型。

不提供：小程序发布、邀请码、匿名账号、密码登录、AI 改写、PWA 安装、桌面专用布局、自动投递、简历代写或无限期服务。

## 2. 页面与信息架构

公开页面：

- `/`：产品价值、三步流程、适用人群、隐私边界、AI 标识与服务周期。
- `/login`：邮箱验证码注册/登录与协议确认。
- `/legal`：用户协议、隐私政策、AI 服务与模型公示信息。
- `/support`：服务阶段、数据导出/删除说明和联系渠道。

登录后页面全部放在 `/app/*`：

- `/app`：当前简历、今日成功额度、岗位入口。
- `/app/resumes*`：四类简历输入、事实核对、默认简历与删除。
- `/app/jobs*`：JD 文字/截图提交及异步进度恢复。
- `/app/results*`：结果、复制与 AI 标识。
- `/app/records*`：投递记录查看；仅 active 期允许修改。
- `/app/preferences`：求职偏好；仅 active 期允许修改。
- `/app/account`：导出、退出登录和自助删除。
- `/app/admin`：只读运营统计；不能提高月度预算上限。

使用 `BrowserRouter`。正式静态托管必须把所有 4xx 回退到 `index.html`，并验证 `/app` 等直达与刷新。

## 3. 身份、协议与租户隔离

- 正式生产只接受 CloudBase 可信上下文中的邮箱注册 UID，命名空间固定为 `web-email-uid-v1`。
- 关闭匿名登录，不接受 OpenID 兼容路径，不迁移旧用户、OpenID 或测试数据。
- 邮箱明文、客户端 UID、OpenID、userId、ownerId 和 identityHash 等身份字段在 API 边界递归删除；业务数据库只保存域隔离后的身份哈希与内部 userId。
- 所有业务查询都附加服务端解析的内部 userId；跨用户资源统一返回不存在或无权访问。
- 用户必须接受当前用户协议与隐私政策。禁用账号仍可读取状态并完成自助删除。

## 4. 核心流程

### 4.1 简历

支持 PDF、DOCX、最多 6 张图片或不超过 20,000 可见字符的文本。文件先校验类型、Magic Bytes、大小、页数和所有权；图片进入腾讯 OCR，文本在进入模型前脱敏。解析结果处于待确认状态，不能直接用于生成。用户确认后只保留结构化事实，原文件删除；24 小时未确认草稿由 cleanup 删除。

最多保存 3 份确认简历。事实使用稳定 `factId` 与哈希，用户修改后重新计算。生成只能使用确认的默认简历。

### 4.2 岗位输入与手机端准备

JD 支持文字或最多 5 张图片。图片选择后立即在 Web Worker/Canvas 中后台压缩并最多并发上传 3 张，但只有用户点击“生成”才创建 OCR/模型任务。

固定候选为 720/Q80、1080/Q78、1440/Q75。选择规则是：在固定评测集中，关键字段保留率至少 99%、无关键字段回归的候选中选字节最小者；全部失败则使用 1440/Q75。该规格必须通过固定 A/B 数据后才写入正式构建配置。

### 4.3 生成与恢复

`generation.create` 快速返回 `{ jobId }`，客户端进入任务页查询 `job.get`。切后台、弱网重连和页面重建后使用 jobId 恢复。OCR、脱敏、JD 结构化、证据选择、Hy3 生成、隐私与非空门禁都在 worker 完成。

失败、超时或 worker 派发失败不得计入每日成功次数；幂等重放不得重复创建任务、调用模型、占用额度或预算。

### 4.4 结果与数据控制

结果页展示正文、AI 标识、复制和记录入口，不提供 AI 改写。`user.export` 以游标分页返回版本化 JSON，浏览器本地组合并下载，不把导出文件写回云存储。自助删除使用二次确认；生产全量退休删除不与自助删除共用入口。

## 5. 服务阶段

```ts
type ServicePhase = "active" | "read_only" | "retired";
type AiAvailability =
  | "available"
  | "budget_paused"
  | "scheduled_closed"
  | "resource_paused";

interface ServiceAccess {
  phase: ServicePhase;
  aiAvailability: AiAvailability;
  aiClosesAt: string;
  dataAccessEndsAt: string;
}
```

- 正式开放时写入 `publicLaunchAt`，由同一配置生成公开首页日期和服务端日期。
- 北京时间满 2 个自然月进入 `read_only`：关闭新的简历解析、生成和业务修改，保留查看、复制、导出与账号删除。
- 满 6 个自然月进入 `retired`：业务数据访问结束，只保留状态/支持和账号删除边界。
- 资源事故可把 AI 标记为 `resource_paused`；预算触线为 `budget_paused`。
- 最终全量删除必须先生成集合与存储清单，再取得一次独立破坏性操作授权。当前代码只提供清单并明确拒绝退休全量删除事件。

`auth.status` 与 `user.get` 返回 `serviceAccess`。首页读取构建期的同一日期配置，不增加匿名业务 API。

## 6. 额度与预算

月度云资源总预算固定 100 元，包含 CloudBase 固定套餐、OCR、TokenHub、数据库、存储和流量；域名一次性费用不计入。预算值以分存储：

- 上限 10,000 分，管理员页面不能修改。
- 8,000 分进入 warning。
- `固定成本 + max(保守结算, 官方账单快照) + 已预留` 在新任务加入后达到 9,000 分时拒绝新 AI 任务，留下 1,000 分账单延迟缓冲。

普通用户：

- 每个北京时间自然日最多 20 次成功生成。
- 同时最多 1 个非终态 AI 任务。
- 任意滚动 10 分钟最多创建 3 次。
- 不设置全站每日次数，不提供管理员临时加量。

`service_config` 保存服务日期、资源暂停与单任务保守预留；`budget_periods` 保存固定成本、预留、保守结算与官方账单快照；`ai_task_admissions` 保存任务级预算预留。正式生产预留通过 CloudBase 事务同时写入预算、成功额度槽、admission 和任务。worker 成功结算，失败、派发失败与 cleanup 超时竞争均幂等释放。

## 7. 数据生命周期

- 简历原件：解析后尽快删除；确认后不得仍有原件。
- JD 图片：OCR/处理后删除。
- 孤立临时文件：最长 1 小时。
- 未确认简历草稿：24 小时。
- 任务预留：10 分钟非终态由 cleanup 回收。
- 操作与审计日志：最长 180 天，且不得含原文、Prompt、正文、凭证或身份原值。
- 用户自助删除：禁用账号并由 cleanup 删除用户范围数据。
- 退休全量删除：只有独立授权后才能实施。

## 8. API 变化

- `generation.create` 保持 `{ jobId }`，新增 `MONTHLY_BUDGET_EXHAUSTED`、`SERVICE_READ_ONLY`、`ACTIVE_JOB_EXISTS` 与 `RATE_LIMITED`。
- 正式 Web 不开放 `generation.rewrite`、邀请码和小程序管理动作。
- `user.export` 返回 `applymate-user-export-v1` 分页数据。
- `admin.stats` 返回固定成本、预留、结算、官方账单快照、预算状态和服务阶段。
- 所有写动作继续要求 UUID requestId 与负载哈希幂等。

## 9. 质量与验收

自动门禁覆盖邮箱登录、协议、四类简历输入、JD 文字/图片、后台压缩、任务恢复、复制标识、记录、导出、自助删除、租户隔离、预算并发、幂等、只读和退休期。

浏览器 E2E 在 320/390/430px 检查触控目标、软键盘、横向溢出、路由直达/刷新和无 Service Worker 缓存。真机覆盖 iOS Safari、Android Chrome 与微信内置浏览器的相册/相机、验证码、后台恢复和剪贴板。

开放注册前执行 30 次真实生成：人工质量均分至少 4.2/5，零虚构、零串台、零未遮盖隐私；选图到正文 P50 不超过 15 秒，P95 不超过 20 秒。TokenHub `hy3` 的额度、价格或质量门任一失败都阻止上线。

## 10. 发布与授权边界

顺序固定：旧环境预发布验证 → 新生产环境关闭 AI 部署 → 域名/HTTPS/备案 → 合成探针 → 两邮箱隔离 → 30 次真实验收 → 专业合规复核 → 开放邮箱注册。

域名购买、套餐开通、新环境创建、备案、密钥、生产部署、预算初始数据和最终全量删除都需要各自单独授权。付款、实名、邮箱验证码、控制台密码由产品负责人本人操作。历史 CloudBase 部署记录不代表当前云端状态；重新登录后的第一次动作只能是只读盘点。

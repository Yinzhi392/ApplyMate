# ApplyMate MVP 实施计划

> 适用对象：执行本项目的 AI 开发者
> 需求基线：memory-bank/design-document.md MVP v1.1
> 技术基线：memory-bank/tech-stack.md MVP v1.0
> 约束：本文只给出实施指令和验证标准，不包含任何实现代码。创建本文不代表授权开始开发。

## 1. 目标与实施原则

本计划用于交付一个面向 30–100 人邀请制内测的微信原生小程序：用户确认一次结构化简历，之后上传或粘贴岗位 JD，系统依据可回溯的真实事实生成个性化开场白，并支持改写、复制、投递记录和数据删除。

执行时必须遵守以下规则：

1. 严格按顺序执行；上一步未通过验证时不得进入下一步。
2. 每一步只完成表格中描述的一项变更，不顺手增加功能。
3. 对可自动化的行为，先建立会失败的测试，再完成最小实现并确认测试通过。
4. 测试数据必须为虚构或脱敏数据，禁止使用真实简历、联系方式和生产数据。
5. 每一步通过后单独提交，提交信息遵循 AGENTS.md。
6. 每个标记为“里程碑”的步骤完成后，必须同步更新 memory-bank/architecture.md。
7. 任何需求冲突以 memory-bank/design-document.md 为准；发现缺口时先更新文档并取得确认，不得自行扩展范围。

## 2. 计划中的目录职责

- miniprogram/：微信原生页面、组件、客户端状态和云函数调用封装。
- cloudfunctions/api/：统一 action 入口、领域服务、仓储、模型适配和安全校验。
- cloudfunctions/cleanup/：临时文件、过期草稿、日志和待删除账号的清理。
- shared/：客户端与云函数共用的请求契约、Schema、错误码和常量。
- tests/unit/：纯业务规则与工具测试。
- tests/contract/：API 和模型适配器契约测试。
- tests/integration/：CloudBase 测试环境中的事务、权限和数据生命周期测试。
- tests/fixtures/：30 组脱敏质量样本及恶意输入样本。
- tests/manual/：微信开发者工具、iOS、Android 和弱网验收记录。
- docs/：隐私、模型评测、发布检查和运维记录。
- memory-bank/：产品设计、技术选型、实施计划、进度和架构事实。

### 阶段 4：幂等与每日额度

| 步骤 | 指令与涉及文件 | 验证测试与通过标准 |

| - [ ] 4.1 | 建立 ai_jobs 的 requestId 认领机制，唯一业务键为用户身份与 requestId。 | 同一用户重复发送相同 requestId；只创建一个任务。不同用户使用相同 requestId 时各自独立。 |
| - [ ] 4.2 | 实现重复请求返回原任务状态或原结果，不重复调用模型。 | 使用模型调用计数器连续重放同一请求；业务响应一致，模型只被调用一次。 |
| - [ ] 4.3 | 建立 daily_usage 文档和北京时间日期键，初始 reserved 与 succeeded 均为零。 | 新用户首次查询、跨北京时间零点查询和旧日期查询；每天得到独立记录，剩余额度计算正确。 |
| - [ ] 4.4 | 在短事务中预留一次额度，确保 reserved 与 succeeded 之和不超过 5。 | 并发发起 6 次预留；恰好 5 次成功，1 次返回额度耗尽，最终计数无负数或超限。 |
| - [ ] 4.5 | 将成功任务的 reserved 原子转换为 succeeded。 | 对同一任务重复完成两次；只转换一次，最终 reserved 减一且 succeeded 加一。 |
| - [ ] 4.6 | 在模型失败、质量门失败或任务取消时释放 reserved。 | 分别模拟超时、429 后失败、非法 JSON 和二次纠错失败；所有情况都释放预留且不增加 succeeded。 |
| - [ ] 4.7 | 确保系统自动重试和自动纠错不再次预留额度。 | 触发一次重试和一次纠错；模型调用次数增加，但 daily_usage 只存在一次预留和一次最终结算。 |
| - [ ] 4.8 | 返回额度耗尽错误及北京时间重置时间，不展示付费引导。 | 在额度为 5 时发起生成与改写；两者均不进入模型，重置时间正确，文案无购买或充值入口。 |
| - [ ] 4.9 里程碑 | 更新 memory-bank/architecture.md，绘制幂等认领、预留、成功和释放的状态说明。 | 用 4.1–4.8 的每个测试场景走读状态说明；每条路径都有终态且不存在额度泄漏。 |

## 4. 最终完成标准

只有同时满足以下条件，AI 开发者才能报告 MVP 已完成：

- 需求追踪表中的 MVP 条目全部有实现与测试证据，所有明确不做项仍未进入产品。
- 自动化测试、CloudBase 集成测试和 iOS/Android 真机清单全部通过。
- 30 组评测零虚构，并达到准确率、合规率、速度、成功率和成本门槛。
- 跨用户隔离、幂等、并发额度、敏感信息遮盖和账号删除演练全部通过。
- 原始简历、JD 图片、日志和个人数据的生命周期符合设计文档。
- 用户协议、隐私政策、AI 标识、模型公示和费用上限已经配置。
- memory-bank/architecture.md 已反映最终实现，且最后一次更新晚于最后一个重大功能。

## 5. 执行停止条件

遇到以下任一情况必须停止并向用户报告，不得自行更换方案或扩大范围：

- 微信个人主体类目、CloudBase 或 TokenHub 无法满足已确认前提。
- memory-bank/design-document.md 与 memory-bank/tech-stack.md 出现无法同时满足的要求。
- 需要新增未批准的框架、数据库、服务器、模型供应商或付费服务。
- 质量、隐私、性能或成本门槛连续两轮无法达到。
- 任何步骤需要使用真实用户简历或生产数据进行调试。
- 用户尚未明确授权进入实际开发。

# ApplyMate MVP 实施计划

**版本：** v1.2

**日期：** 2026-08-05

**依据：** [`design-document.md`](./design-document.md)、[`tech-stack.md`](./tech-stack.md)、[`architecture.md`](./architecture.md)

**适用对象：** 执行本项目的 AI 开发者

**当前边界：** 文档确认前不得创建业务代码、开通外部资源或调用付费能力。

## 1. 执行规则

1. 写任何代码前，完整阅读 [`architecture.md`](./architecture.md) 和 [`design-document.md`](./design-document.md)，再阅读本计划当前阶段。
2. 严格按阶段顺序执行；未满足阶段出口条件时不得进入下一阶段。
3. 每一步只完成一项小变更，并执行该行指定的验证；失败时先修复，不得带错继续。
4. 每完成一步立即更新 [`progress.md`](./progress.md)，记录日期、结果、测试证据和阻塞项。
5. 相关步骤形成可运行、可验证的子功能后再提交，整个 MVP 预计 20–30 次提交；不为每一行机械提交。
6. 每个重大里程碑更新 [`architecture.md`](./architecture.md)，写明实际结构、数据流、关键决策和已知限制。
7. 禁止提交真实简历、原始 JD 截图、OpenID、密钥、生产导出或未脱敏日志。
8. 当前无 Git 远程，只执行本地格式、类型、测试和构建检查；配置 GitHub 后才增加 CI。
9. 所有外部资源均视为未准备。创建微信、CloudBase、OCR 或 TokenHub 资源前必须分别取得产品负责人明确授权。
10. 严格零付费：任何免费额度、后付费关闭或账单为零的条件无法满足时，立即停止阶段 0，不得自行付费或更换平台。

## 2. 计划目录

- `miniprogram/`：微信原生小程序页面、组件、样式和客户端服务。
- `cloudfunctions/api/`：鉴权、action 路由、任务创建/查询和轻量业务操作。
- `cloudfunctions/worker/`：OCR、脱敏、解析、生成、改写和质量门。
- `cloudfunctions/cleanup/`：超时任务、残留文件、过期数据和账号物理删除。
- `shared/`：API、领域 Schema、错误码、状态机、限制常量和纯函数。
- `tests/fixtures/`：经确认的脱敏简历、JD、图片和恶意输入样本。
- `docs/`：线框、评测、隐私、协议、合规、测试和发布记录。
- `memory-bank/`：设计、技术、实施、进度和架构记忆。

这些目录只在阶段 0 获得继续授权后创建。

## 4. 提交建议

20–30 次提交应按可运行子功能组合，建议边界为：骨架、共享规则、身份协议、邀请、任务状态、幂等额度、文件输入、OCR 脱敏、简历解析、简历管理、JD 解析、用户确认、生成质量门、改写、投递记录、反馈、删除清理、管理员、各主要页面组、指标安全、发布文档。

每次提交前必须：更新 progress；如属于里程碑则更新 architecture；运行与变更相关的测试；运行本地全量检查；确认无密钥和真实用户数据。

## 5. 全局停止条件

出现以下任一情况立即停止并向产品负责人报告，不得自行扩大范围：

1. 产品设计、技术栈或本计划尚未明确确认。
2. 需要创建或开通外部资源但未取得该资源的单独授权。
3. OCR、TokenHub、CloudBase、存储或流量无法严格保持实际费用为零。
4. 30 组样本未全部人工确认，或准确率、合规率、虚构、耗时任一门槛未通过。
5. 微信个人主体类目不允许正式发布；此时仅可继续体验版测试。
6. 必须升级主体、转 H5、换云平台、增加付费、收集手机号或引入未批准第三方。
7. 发现原图流向 TokenHub、脱敏信息外泄、跨用户访问或账号删除不彻底。
8. 需要产品负责人作出会改变范围、数据处理或用户体验的决定。

停止报告必须写清已完成步骤、测试证据、具体阻塞、是否产生费用、可安全保留的本地状态，以及等待产品负责人决定的事项。

## 历史：真机真实性误判与点击生成时延修复（2026-08-22，已被低延迟 v2 取代）

- **真实根因：** 最近三次真机失败任务均安全记录 `validationGate=jd_field_not_in_current_input`，云端创建到失败分别约 8.6、9.4 和 10.1 秒。旧门会校验模型返回的全部 JD 数组，即使某个辅助字段没有被核心职能、匹配计划或正文引用；同时 `AIAgent`/`AI Agent` 的空格差异会造成专业词误判，“资本市场”中的“资本”也会被组织名正则误判。失败不是 30 秒模型超时，也不是已确认的简历事实虚构。
- **真实性门修复：** Prompt 要求 JD 数组优先保留当前 OCR 原文片段；校准器先过滤未获当前 JD 支持且未被使用的辅助字段，再重建核心字段索引。`AI Agent` 等拉丁专业词采用去空格归一，“资本市场”不再被当作公司名。被核心职能或证据实际引用的字段仍必须有当前 JD 锚点；跨 JD 术语、虚构组织或数字继续失败关闭，事实、证据、PII 和正文格式门不变。
- **交互修复：** 选择 JD 截图只保存本地路径并立即显示，不执行压缩或上传。点击“识别并生成”后，每张图按“压缩完成即上传”独立并发处理，保持图片顺序且上传失败继续回收已成功文件。
- **时延修复：** `generation.create` 在异步派发后执行 14 次有界短轮询，最长约 9.75 秒；常见 8–10 秒任务可在首次请求中直接返回 `applicationId`，避免手机进入任务页后再进行多轮跨网查询，超出窗口仍返回 `jobId` 并保留恢复能力。客户端随请求记录 `clientImagePreparationMs`，worker 记录输入/OCR、模型和总耗时及管线版本，只保存数字，不保存截图、OCR 原文或正文。点击到结果目标 ≤15 秒、争取约 10 秒，但仍需新客户端真机计时后才能验收。
- **部署证据：** 产品负责人授权后已于 2026-08-22 分别部署 `api` 与 `worker`，未部署 `cleanup`、未上传或发布小程序。两者只读健康检查均为 `experience_real_ai_live / acceptsUserTraffic=true`；`worker` 配置诊断确认模型、OCR 与 CloudBase 凭证存在。健康检查未调用 OCR 或 TokenHub 模型。
- **本地证据：** 新增未使用辅助字段过滤、`AI Agent` 紧凑写法、“资本市场”组织误判、跨 JD、客户端分段耗时和 API 有界终态合并回归；相关聚焦测试 31 项通过。完整 `npm run check` 通过格式、fixture 隔离、敏感扫描、类型检查、121 个测试文件共 611 项测试和五模块构建。

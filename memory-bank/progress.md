## 阶段 2 逐步记录

- **2.1 文本规则：** 已以失败测试起步，实现 Unicode 字素级可见字符计数（空白不计）和非空段落拆分。中英文、组合 emoji、组合字符、标点、空白、空段及 250/350 精确边界测试通过；`npm run typecheck` 通过。
- **2.2 限制常量：** 已集中定义图片数、10MB 单文件/图片总量、PDF 10 页、20,000 字、偏好/反馈 500 字和 3 份简历上限。17 项边界测试覆盖零值、精确上限、超一单位、负数及非整数并通过。
- **2.3 本地脱敏：** 已以失败测试建立手机号、邮箱、身份证、护照式证件号和详细地址的确定性遮盖。输出只保留遮盖类型及原文位置；标点、大小写、电话分隔符和常见误报测试通过，并补获、修复证件号后缀边界问题。
- **2.4 事实身份：** 已定义九类事实来源、NFC/空白归一、SHA-256 文本哈希和带版本域隔离的 24 位摘要 `factId`。等价文本稳定，来源或文本变化会更新 ID，200 组合成事实无碰撞。
- **2.5 求职偏好：** 已按句号、问叹号、分号或换行拆分，经空白归一后去重，并生成来源固定为 `preference` 的事实。500 字精确边界允许，501 字拒绝，空输入与重复句测试通过。
- **2.6 简历 Schema：** 已用 Zod 定义严格 `ResumeProfile`，覆盖教育、经历、项目、技能、语言、证书、成果、偏好及其他事实。稳定 ID/哈希为必填，单项事实最多 2,000 个可见字符，未知字段拒绝；合法与三类非法样本均通过预期测试。
- **2.7 JD 契约：** 已定义严格字段 ID、0–1 置信度、六类关键字段和 0.8 确认阈值。岗位名缺失或关键字段低置信会等待确认；公司名缺失合法并使用“贵司”及提醒。重复 ID 与无效置信度测试会被拒绝。
- **2.8 逐项证据：** 已定义严格陈述、事实来源和 JD 来源 Schema，并用当前事实/JD ID 注册表验证实际归属。无来源、格式错误、未知来源会失败；单项陈述可合法映射多个来源，重复陈述 ID 被拒绝。
- **2.9 任务状态：** 已固定 8 个英文状态标识及中文展示名，并用 8×8 穷举测试锁定转换图。文本任务可跳过 OCR；成功与失败都是不可再次前进的终态。
- **2.10 API 契约：** 已锁定 24 个 action、7 个只读 action、写请求 UUID 幂等键、20,000 可见字符负载上限、统一成功/失败响应和 11 个错误码。读请求可省略 requestId；未知 action、无效 UUID、超长或危险对象键会拒绝。
- **2.11 AI 质量门：** 已实现 250–350 可见字符、2–3 段、简体字符、当前证据归属、陈述原文覆盖、数字来源、敏感信息、提示指令和 Unicode 合法性硬校验。合法样本通过；短、长、段落错误、繁体、无来源数字、电话和孤立代理字符分别被拒绝。
- **2.12 手动编辑：** 已复用同一检测器但转换为非阻断警告。相同的短文本与无来源数字在手动模式仍可保存/复制，在 AI 生成模式则硬失败，行为分离测试通过。
- **2.13 复制标识：** 已锁定“正文 + 单个换行 + `AI生成内容，请核对真实性`”的纯函数，去除正文尾部空白但不改变正文内容。测试证明标识另起一行且不计入正文 250 字边界。
- **2.14 安全回归与收尾：** 已覆盖提示注入、原型污染式键、100,000 字负载和 API/模型正文中的孤立 Unicode 代理字符；全量 18 个测试文件、72 项测试及构建通过。架构、实施计划、共享说明和贡献者指南已同步，阶段 2 形成独立本地提交。

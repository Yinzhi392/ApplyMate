## 阶段 3 逐步记录

- **3.1 API 注册表：** 已以失败测试起步建立显式 action 注册表。已注册动作可调度；未知与大小写变体统一拒绝，处理器异常只返回通用错误，不泄漏内部路径或堆栈。5 项专项测试与类型检查通过。
- **3.2 可信身份边界：** 已建立不依赖 SDK 的 CloudBase 上下文读取端口和统一 API 入口。仅受信 `OPENID` 生效；请求包或 payload 中伪造的 OpenID/userId 被忽略，缺失/空值/非字符串上下文统一未认证，畸形请求不返回 Zod 或内部细节。3 项专项测试通过。
- **3.3 用户生命周期：** 已建立哈希身份、稳定 userId、启用/禁用和待邀请码/已激活状态。相同可信身份并发首次访问仅创建一条记录，原 OpenID 不落入用户记录；不同身份生成隔离记录，禁用账号仅允许状态、个人资料和后续删除流程动作。3 项专项测试通过。
- **3.4 协议版本：** 发现原 24 个 action 缺少保存协议同意的入口，按既定产品流程补充要求 requestId 的 `agreement.accept` 写动作；持久幂等映射仍按计划在阶段 4 实现。用户协议与隐私政策保存各自版本及同一接受时间；未同意、旧版本和版本实质变化均阻断业务，客户端伪造旧/未知版本拒绝。5 项 API/协议专项测试通过。
- **3.5 状态与个人资料：** 已将用户、协议和管理员白名单接入 `auth.status`、`agreement.accept`、`user.get` 三个动作。新用户、待邀请码、已激活、管理员、禁用和协议变更六态均可区分；个人资料不返回 identityHash 或 OpenID，伪造 userId 仍只得到当前用户。DomainError 保留安全业务码，未知异常仍统一隐藏。9 项相关测试通过。
- **3.6 邀请码消费：** 已实现邀请码规范化哈希、7 天过期、撤销和一次性消费。仓库只保存哈希；消费邀请码与激活用户在同一原子操作内完成，同码并发仅一次成功，过期时刻、撤销码和已用码均拒绝。3 项邀请码服务测试及类型检查通过。
- **3.7 管理员启动：** 已接入 `admin.inviteCreate`、`admin.inviteRevoke` 和 `invite.activate`。白名单身份完全来自受信 OpenID；管理员必须先接受当前协议，创建时仅向本次响应返回邀请码明文，普通用户无法通过负载伪造身份。管理员创建/撤销与普通用户激活共 3 项接口测试通过。
- **3.8 求职偏好：** 已接入 `user.updatePreferences`，仅允许已同意协议且已激活的用户（或白名单管理员）修改。自由文本按共享规则生成稳定 preference factId；支持新增、整体替换和清空，500 个可见字符可保存，501 个拒绝且不覆盖旧值。2 项接口测试及类型检查通过。
- **3.9 用户启停：** 已接入 `admin.userSetEnabled`。只有来自受信上下文、已接受当前协议且账号启用的白名单管理员可操作；普通用户和负载伪造管理员均失败。目标状态与审计记录原子保存，审计仅含内部 userId、原因、时间和变更值，不含 OpenID。禁用用户仍可读取状态，但业务写入被阻止。1 项接口测试及类型检查通过。
- **3.10 集成与收尾：** 已通过管理员接受协议并创建首码、两个普通用户同码并发、跨用户伪造读取、旧协议阻断、管理员禁用的完整本地链路。伪造目标 userId 只返回当前用户资料且偏好互不泄漏。架构、设计、技术栈、API 说明和本计划已同步；全量 28 个测试文件共 102 项测试及四模块构建通过。

## 阶段 2 逐步记录

- **2.1 文本规则：** 已以失败测试起步，实现 Unicode 字素级可见字符计数（空白不计）和非空段落拆分。中英文、组合 emoji、组合字符、标点、空白、空段及 250/350 精确边界测试通过；`npm run typecheck` 通过。
- **2.2 限制常量：** 已集中定义图片数、10MB 单文件/图片总量、PDF 10 页、20,000 字、偏好/反馈 500 字和 3 份简历上限。17 项边界测试覆盖零值、精确上限、超一单位、负数及非整数并通过。
- **2.3 本地脱敏：** 已以失败测试建立手机号、邮箱、身份证、护照式证件号和详细地址的确定性遮盖。输出只保留遮盖类型及原文位置；标点、大小写、电话分隔符和常见误报测试通过，并补获、修复证件号后缀边界问题。
- **2.4 事实身份：** 已定义九类事实来源、NFC/空白归一、SHA-256 文本哈希和带版本域隔离的 24 位摘要 `factId`。等价文本稳定，来源或文本变化会更新 ID，200 组合成事实无碰撞。
- **2.5 求职偏好：** 已按句号、问叹号、分号或换行拆分，经空白归一后去重，并生成来源固定为 `preference` 的事实。500 字精确边界允许，501 字拒绝，空输入与重复句测试通过。
- **2.6 简历 Schema：** 已用 Zod 定义严格 `ResumeProfile`，覆盖教育、经历、项目、技能、语言、证书、成果、偏好及其他事实。稳定 ID/哈希为必填，单项事实最多 2,000 个可见字符，未知字段拒绝；合法与三类非法样本均通过预期测试。
- **2.7 JD 契约：** 已定义严格字段 ID、0–1 置信度、六类关键字段和 0.8 确认阈值。岗位名缺失或关键字段低置信会等待确认；公司名缺失合法并使用“贵司”及提醒。重复 ID 与无效置信度测试会被拒绝。
- **2.8 逐项证据：** 已定义严格陈述、事实来源和 JD 来源 Schema，并用当前事实/JD ID 注册表验证实际归属。无来源、格式错误、未知来源会失败；单项陈述可合法映射多个来源，重复陈述 ID 被拒绝。
- **2.9 任务状态：** 已固定 8 个英文状态标识及中文展示名，并用 8×8 穷举测试锁定转换图。文本任务可跳过 OCR；成功与失败都是不可再次前进的终态。
- **2.10 API 契约：** 已锁定 24 个 action、7 个只读 action、写请求 UUID 幂等键、20,000 可见字符负载上限、统一成功/失败响应和 11 个错误码。读请求可省略 requestId；未知 action、无效 UUID、超长或危险对象键会拒绝。
- **2.11 AI 质量门：** 已实现 250–350 可见字符、2–3 段、简体字符、当前证据归属、陈述原文覆盖、数字来源、敏感信息、提示指令和 Unicode 合法性硬校验。合法样本通过；短、长、段落错误、繁体、无来源数字、电话和孤立代理字符分别被拒绝。
- **2.12 手动编辑：** 已复用同一检测器但转换为非阻断警告。相同的短文本与无来源数字在手动模式仍可保存/复制，在 AI 生成模式则硬失败，行为分离测试通过。
- **2.13 复制标识：** 已锁定“正文 + 单个换行 + `AI生成内容，请核对真实性`”的纯函数，去除正文尾部空白但不改变正文内容。测试证明标识另起一行且不计入正文 250 字边界。
- **2.14 安全回归与收尾：** 已覆盖提示注入、原型污染式键、100,000 字负载和 API/模型正文中的孤立 Unicode 代理字符；全量 18 个测试文件、72 项测试及构建通过。架构、实施计划、共享说明和贡献者指南已同步，阶段 2 形成独立本地提交。

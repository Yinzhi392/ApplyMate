# ApplyMate 微信小程序

阶段 9 使用微信原生 TypeScript、WXML 和 WXSS；阶段 10 新增协议查看、AI 模型公示和最小分析事件。当前默认运行本地演示 API，用于在不创建 CloudBase、OCR 或 TokenHub 资源的情况下验证完整页面流程。

## 本地打开

1. 在微信开发者工具中导入仓库根目录。
2. 仅使用模拟器时可保持 `touristappid`；需要真机预览时使用你自己的合法微信 AppID。两种方式都必须确认小程序目录为 `miniprogram/`。
3. 首次打开本轮视觉返工时，执行“清缓存 → 清除全部缓存”，再点击“编译”，避免开发者工具继续使用旧 WXSS 编译产物。
4. 编译后从登录页开始，在同一页面输入邀请码、勾选协议并验证。
5. 本地演示邀请码为 `APPLYMATE`。该值只写在开发说明中，不会显示在小程序登录界面。

演示状态仅保存在本次小程序进程中，重新编译会重置。最后一次任务 ID 使用本地存储保存，用于验证页面重建后的任务恢复。打开/复制的失败重试队列最多 20 条，只保存事件名和可选 applicationId，不保存正文。即使使用真实微信 AppID，当前版本仍运行本地演示 API，不代表真实微信身份、CloudBase 或正式邀请码系统已经接入。

## 建议验收路径

- 首次准入：同意协议，尝试无效邀请码，再使用演示邀请码。
- 简历：在“上传文件／粘贴文字”间切换，分别验证文字、PDF、DOCX 和图片选择；确认结构化事实并设置默认简历。
- 首页：确认只显示当前简历、今日额度和“提交岗位信息”，最近投递只在记录页出现。
- 岗位：一次批量选择或分批补充最多 5 张截图，验证删除、长按拖动排序；切换到文字模式再切回时，两边草稿都应保留。提交后应直接生成，不出现岗位确认页。
- 连续投递：完成一次简历核对后，连续提交两个不同 JD；两次都应直接进入生成任务，不重复核对个人资料。
- 结果：首屏编辑短正文查看非阻断警告；保存、改写、复制，并确认页面与剪贴板末行均显示 `AI生成内容，请核对真实性`。体验版默认展示真实模型披露；只有显式 demo 模式才显示“本地演示数据，未调用真实 OCR 或模型”。再展开匹配依据和投递次级操作。
- 连续岗位：结果页点击“继续投下一个岗位”应进入空白岗位草稿且保留默认简历；点击“返回首页”不得溢出、裁切或堆积导航页面。
- 记录：切换未投递/已投递，确认最近投递都集中在此；保存备忘和覆盖反馈，再删除单条记录。
- 我的：编辑偏好，打开“协议与隐私”切换三份文本并检查版本/同意时间/复制全文，再验证账号删除二次确认。

管理员页面默认不可见，直接访问也会被本地 API 拒绝。管理员演示状态已由自动化测试覆盖；真实白名单验证必须等待 CloudBase 获得单独授权。

微信开发者工具和真机中的原生呈现是阶段 9 的视觉验收基准，浏览器预览只作为结构与设计方向参考。请至少检查 iPhone 12/13、320px 或 375px 小屏以及一种 Android 机型，确保按钮与长文字不越过页面边距。

## 本地验证

```sh
npm run check
npx vitest run tests/unit/miniprogram-*.test.ts tests/integration/miniprogram-*.test.ts
```

当前代码不得加入 `wx.cloud` 调用。真实文件上传、微信身份、OCR、模型、云端异步任务和真机跨端行为均需在外部资源逐项获批后验证。
